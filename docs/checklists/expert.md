# Expert Checklist

Use this checklist after Stage 4.

- [ ] I run `go vet ./...` and `go test ./...` before publishing changes.
- [ ] I run race checks for concurrent code.
- [ ] I can decide which package owns a new concept.
- [ ] I can design a small public API with clear failure behavior.
- [ ] I can document invariants and complexity in a topic README.
- [ ] I can add directory, catalog, and knowledge graph entries for new topics.
- [ ] I can identify when benchmark or pprof work is required.
- [ ] I can review code for behavior regressions, missing tests, and maintainability risk.
